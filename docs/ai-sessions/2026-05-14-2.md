## 메모

- **카카오 알림 트랜잭션 분리**: createOrder() 내부에서 HTTP 호출하면 DB 커넥션을 점유한 채 외부 I/O 대기. 컨트롤러에서 커밋 후 별도 호출로 분리해 커넥션 유지 시간 최소화.
- **Pessimistic Lock 적용 위치**: OptionRepository.findByIdWithLock()에만 @Lock 추가. SELECT FOR UPDATE로 첫 트랜잭션이 커밋될 때까지 두 번째 요청 대기 → 업데이트된 재고 기준으로 처리됨.
- **동시성 테스트 디버깅**: Lock 없이는 Lost Update(successCount=2) 예상했으나 실제로는 MySQL InnoDB 데드락(SQL Error 1213) 발생. 테스트를 unexpectedFailCount 카운터로 세분화해 비즈니스 규칙(IllegalArgumentException)과 DB 오류를 구분.
- **Fake vs MockBean**: @MockBean은 Mockito의 verify/when 문법이 필요. FakeMessageClient(@Primary, @Component)는 순수 Java로 sendCount를 추적하므로 더 읽기 쉽고 테스트 의도가 명확함.
- **@Transactional + dirty checking**: 트랜잭션 내에서 Entity를 수정하면 flush 시 자동으로 UPDATE 쿼리가 발생. 별도 save() 호출 불필요. @Transactional이 없으면 detached 상태라 save() 필수 — 두 변경을 반드시 함께 적용해야 한다.
