## 메모

- **FakeKakaoLoginClient 상속 방식**: Kakao 전용 클라이언트는 인터페이스 추상화 실익이 없다. 상속으로 HTTP 메서드만 오버라이드하는 방식이 더 단순하고 production 코드 구조 변경이 없다.
- **ALREADY_PASSES 사이클**: 사이클 1~4, 9~10은 KakaoAuthService 구현이 이미 올바른 동작을 하고 있어 테스트 작성 즉시 Green이었다. 이는 기존 Controller 로직이 정확했음을 방증한다.
- **inner record → top-level 분리**: `KakaoTokenResponse`, `KakaoUserResponse`를 별도 파일로 분리해 참조가 `KakaoLoginClient.KakaoTokenResponse` → `KakaoTokenResponse`로 단순해졌다.
