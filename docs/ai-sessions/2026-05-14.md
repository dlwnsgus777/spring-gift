## 메모

- **테스트 격리 교훈**: 서비스 테스트에서 시드 데이터(memberId=2) 의존은 병렬 실행 시 위험. MemberRepository로 실제 Member를 생성하고 그 ID를 사용하면 완전히 격리됨. @Transactional 롤백이 보장하므로 다른 테스트에 영향 없음.
- **비대칭 FK 설계 이해**: Wish.memberId(Long)은 인증 토큰에서 이미 얻으므로 엔티티 조인 불필요. Wish.product(@ManyToOne)은 응답에 상품 정보가 필요해 즉시 로딩 필수. 접근 패턴이 설계를 결정한 사례.
- **WishResult 위치 결정**: 처음엔 WishCommandService 내부 레코드로 생성했으나 gift.wish 패키지 독립 파일로 분리. 다른 클래스에서 참조할 때 WishCommandService.WishResult처럼 쓸 필요 없어 가독성 향상.
- **다음 단계**: 8단계 Order 도메인 — 트랜잭션 경계 증명, 위시리스트 자동 삭제, 5개 Repository 의존 제거가 핵심.
